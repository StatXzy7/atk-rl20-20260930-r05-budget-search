# 预算约束确定性环境中的 UCT 与精确最短成本求解器对比

在确定性、可哈希 Markov 状态、正整数动作成本、含转置与环的工具环境中搜索动作
序列。方案只有在**累计成本 ≤ 执行预算**且**终点成功**时有效，目标是有效方案中
成本最低者。本仓库实现：

- 一个完整定义的 **UCT (UCB1) 图搜索 Agent**；
- 一个**独立的精确最短成本求解器**（预算受限 Dijkstra）作为 oracle；
- 可保存/恢复的**显式随机数状态**，保证 `(输入, 种子, 调用预算)` 可重放；
- 一个确定性的**“仅按环境状态粗暴去重”反例**；
- 自动化测试与**搜索调用预算曲线**实验。

仅依赖 Python 3.9+ 标准库，不接入任何外部模型。

## 运行

```bash
python3 -m unittest discover -s tests          # 29 tests
python3 scripts/experiments.py                 # 生成 reports/budget_curve.csv 与 reports/summary.txt
```

## 环境接口（`budget_uct/env.py`）

- `initial_state()`、`actions(s)`、`step(s,a) -> (s', cost)`、`is_success(s)`。
- `cost` 为严格正整数（构造期校验，`bool` 也拒绝）。
- `InstrumentedEnv` 包装器负责**真实转移调用**计费：每个 `(state, action)` 第一次
  查询记一次 `real_calls`，之后的重复查询记 `cache_hits`，**缓存命中绝不冒充新调用**。
  列举合法动作 `actions` 与成功判定 `is_success` 不计费；只有 `step` 计费。
- `GraphEnv` 为显式有限转移表，允许任意转置与环；`execute_plan` 逐步执行并在非法
  动作时抛错。

## UCT 完整规则（`budget_uct/uct.py`）

**搜索节点键。** 节点键为 `(环境状态, 剩余预算)`。到达相同环境状态但剩余预算不同
时，动作的可负担集合不同，因此**不无条件合并**。正整数成本保证从根沿任意路径剩余
预算严格递减，键空间有限，搜索必然可终止。

**转置与有环图适配。** `(state, remaining)` 相同的到达共享同一个 `UCTNode`，但
**每条入边是各父节点私有的 `Edge`**，各自保存 `visits / reward_sum / blocked /
child_key / cost`。节点上没有“唯一父指针”；回传沿**本次下降实际走过的
(node, edge) 具体路径**进行，因此共享节点不会把奖励错误地回给某个单一父亲，也不会
因环而重复计数。选择阶段另加环守卫：不走向已在本次下降路径上的子节点，避免同一路径
自转。

**选择 (Selection)。** 节点一旦被访问就惰性展开其全部合法动作边。下降时若存在未试
边则停止下降进入扩展；否则在可负担（`not blocked`）且不闭环的边上按 UCB1 取值：

```
Q(e) = mean(e) + c * sqrt( ln N(parent) / n(e) ),    c = sqrt(2)
```

`mean = reward_sum / visits`；平局按动作顺序打破（不消耗 RNG，严格确定）。死路或所
有动作都付不起时，该叶奖励 0。

**扩展 (Expansion)。** 从未试、可负担边中用 `rng.choice` 随机取一条，调用一次
`step`（真实计费一次）得知成本：成本超过剩余预算则永久标记 `blocked` 并回传 0；否则
取得/创建 `(s', remaining - cost)` 子节点。扩展即终点成功则记成功并回传 1。

**模拟 (Simulation / Rollout)。** 从扩展子节点（或无调用预算时的当前节点）开始，采
用**均匀随机策略**：依次探测当前状态全部合法动作（已缓存为命中、未缓存则真实计费），
在“成本 ≤ 剩余预算”的集合上 `rng.choice` 均匀选一个。遇到成功结束（奖励 1）、死路、
无付得起的动作、或调用预算耗尽（奖励 0）时停止。**模拟与树内转移使用同一计费口径**。

**叶子估值与奖励。** 二值奖励：终点成功且成本不超预算为 1，否则 0；无启发式估值函数
（未扩展叶不引入先验，价值由模拟产生）。

**回传 (Backpropagation)。** 将奖励沿本次具体路径对每个节点与每条边各加一次
`visits += 1`、`reward_sum += reward`；路径上的转置节点只更新一次。

**“发现任意可行解”与“当前最好解成本”分离。** 奖励通道只驱动 UCB 探索；另外维护
incumbent：每次成功（树前缀成功或模拟成功）都独立地把**具体动作序列**重新执行一遍
做准入校验——逐步合法、总成本 ≤ 预算、终点成功——仅当总成本严格更小时更新
`best_plan / best_cost`。因此 UCT 永远不会因节点合并而吐出越界或不可执行方案。

**随机数与重放。** 全部随机性来自单个 `random.Random(seed)`；`save()` 快照包含
RNG 状态、调用/命中计数、迭代与模拟次数、incumbent、整棵搜索表以及**环境转移缓存**
（均深拷贝）。`restore()` 可在一个全新包装器上重建计费状态并继续，与未中断轨迹逐位
一致。

**计费与停止。** 是否开始一个新的 trial 在 trial 边界判定；每个 trial 一旦开始就
完整执行（扩展一次 + 随后的 rollout），其 RNG 轨迹**不依赖**调用方如何切分调用预算，
因此分块续搜与一次性运行在同一 trial 前缀上完全一致。达到新增真实调用目标后，
`search_uct(..., )` 再跑一个有界、确定的纯缓存“打磨”窗口（`max(32, 2·|节点|)` 次
trial），或在可达有限图全部展开时停止；低层 `UCTSearcher.run(call_budget)` 默认不打磨，
便于按相同分块严格续搜。最后一个 rollout 可能探测若干新转移而**小幅、有界地越过**目标
调用数（越界上限为一次 rollout 探测到的不同 `(state, action)` 数），但方案的执行预算
校验独立，任何候选都必须重新执行且总成本 ≤ 执行预算才会进入 incumbent。UCT 的返回
**不证明最优**、**不证明无解**：`optimal_cost` 恒为 `None`，
`proven_optimal/proven_infeasible` 恒为 `False`。未找到解仅表示该调用预算与种子下没找到。

### 支配剪枝的成立条件（本实现默认不启用）

在节点键为 `(state, remaining)` 时，可用更松的支配关系剪枝：节点 A（state=x,
remaining=rA）支配节点 B（state=x, remaining=rB）当且仅当 `rA ≥ rB`，**并且**

1. 状态是 Markov 的：未来（合法动作、转移、成本、成功判定）只依赖状态，不依赖到达
   路径或历史；
2. 成本可加且目标只看累计成本与终点成功，剩余预算更多永远不会使任何方案从可行变为
   不可行（动作集与成本不随预算改变）。

此时 B 付得起的每一条后缀动作，在 A 处同样付得起；A 的可达成功最小后缀成本不会比 B 差，故保留 A、删除 B 不损失最优性。
若合法动作/成本依赖历史、存在资源型副作用，或成功还依赖路径，则该支配不成立。
本实现直接保留不同 remaining 的节点以保证语义清晰，未启用该剪枝。

## 精确求解器（`budget_uct/exact.py`）

预算受限 Dijkstra：边权为正整数动作成本，只松弛 `new_cost ≤ budget`；堆平局用单调
计数器确定化；首次 settle 成功状态即得最优成本并用 `prev` 重建路径。若堆在预算内
排空仍未 settle 成功状态，则给出**预算内无解证明**。若提供 `call_budget` 且提前耗尽，
返回 `budget_exhausted` 且 `proven=False`（不得当作无解证明）。正权保证不同成本的环
永远不会以更小距离松弛已 settle 状态。

## 环境（`budget_uct/environments.py`）

- `demo_env`：转置（`s2`、`s3`、`s6` 汇入 `s5`）、陷阱支路（`s2→t9→t10` 死循环）、
  不同成本环（`s5` 上成本 1 与成本 3 的自环）、回边（`s1→s0`）。最优成本 6
  （`to_s2, merge, goal`）；预算 4 可证无解。
- `dedup_counterexample_env`：去重反例（下详）。
- `layered_env(layers, width)`：分层有限环境，含前向边、廉价回边/自环、死端列，构造
  用独立种子 RNG，用于预算曲线。

## “仅按状态去重”反例（`budget_uct/naive_dfs.py`）

环境 `s0 --expensive(12)--> X --go(3)--> G` 与 `s0 --cheap(4)--> X --go(3)--> G`，
预算 12，DFS 按动作成本降序确定性探索：

1. 先走 expensive：到 `X` 时剩余 0，付不起 `go(3)`；仅按状态记忆的 DFS 把 **X**
   标记为“不可达成功”；
2. 再走 cheap：到 `X` 时剩余 8，本可 `go` 成功（总成本 7 ≤ 12），但 X 已被全局标记
   为坏，于是**错误报告无解**。

以 `(state, remaining)` 为记忆键时正确找到 `['cheap','go']`（成本 7），与精确 oracle
一致。该模块同时用 `InstrumentedEnv` 计费；测试固化该假阴性。UCT 自身以
`(state, remaining)` 为键且 incumbent 准入重新执行方案，因此不会越界，测试断言其表
中同一环境状态 X 出现在多个不同剩余预算下。

## 搜索预算曲线（`reports/`）

分层环境（`layers=6, width=4`，oracle 最优成本 6，执行预算 14，20 个种子）的典型结果
（`python3 scripts/experiments.py` 重新生成；详见 `reports/summary.txt` 与
`reports/budget_curve.csv`）：

| 调用预算 | 发现率 | 最优率 | 平均成本 | 最差差距 |
|---:|---:|---:|---:|---:|
| 8 | 0.05 | 0.00 | 11.00 | 5 |
| 16 | 0.05 | 0.00 | 11.00 | 5 |
| 24 | 0.20 | 0.00 | 12.00 | 8 |
| 32 | 0.20 | 0.00 | 12.00 | 8 |
| 44 | 0.50 | 0.00 | 11.30 | 8 |
| 56 | 0.70 | 0.00 | 10.86 | 7 |
| 74（图穷尽于 74 次真实调用） | 1.00 | 0.05 | 8.85 | 5 |

观察：发现任意可行解先于成本收敛；真实转移在 74 次后全部缓存，更大调用预算不再提供
新信息；部分种子受 UCB/均匀模拟的早期路径锁定停在次优——**这正说明探索所得最好解不
能被声明为已证最优**，最优/无解判定必须交给独立精确求解器。实验还对每条 UCT 方案做
可执行性、预算与最优性差距校验，非法/越界方案数为 0。

## 代码结构

- `budget_uct/env.py`：环境协议、图环境、调用计费、方案执行。
- `budget_uct/exact.py`：预算受限 Dijkstra oracle（最优/无解证明）。
- `budget_uct/uct.py`：UCT 搜索、边/节点统计、快照恢复、incumbent。
- `budget_uct/naive_dfs.py`：确定性记忆化 DFS（两种去重键，反例）。
- `budget_uct/environments.py`：演示/反例/分层环境。
- `scripts/experiments.py`：oracle 校验、预算曲线、差距统计、CSV/文本报告。
- `tests/`：29 个 `unittest` 用例。
